# PicaComic CBZ与元数据导出改造开发计划（全量基线规划文档）

## 一、 项目背景与改造目标
针对 PicaComic 进行专项深度定制改造，使其成为以 **同人志 / 短篇单行本** 为核心的高效阅读、管理与归档工具。
改造的核心目标是：
1. **下载结构极简化**：下载根目录下只保留 `.cbz` 压缩包和核心数据库，彻底消除零散文件夹和图片碎片。
2. **元数据完美兼容**：在打包 `.cbz` 时内嵌标准 `ComicInfo.xml`，且支持中文标签翻译与原始平台固定主站溯源，无缝对接 Komga / Kavita / 阅读器等媒体生态。
3. **交互快捷化与手势分区**：
   - 为 EH 和 JM 等平台添加默认下载规则开关，跳过繁琐的二次确认弹窗。
   - 改造下载列表卡片交互：短按封面缩略图直接进详情页，短按以外大片区域（标题/空白）直接秒进阅读器，长按缩略图唤出离线选话抽屉，长按以外区域进入多选批量管理。
4. **零冲突外挂式架构**：所有新加的设置项、元数据生成器、流式解压器均采用“独立外挂”形式，最小化修改原项目核心代码，保障未来上游合并（`git merge upstream/master`）时零冲突。

## 二、 关键技术方案选型与讨论决策结论

| 决策维度 | 选定方案 | 决策依据与深度原理 |
| :--- | :--- | :--- |
| **旧数据兼容** | 不考虑旧数据兼容 | 彻底放弃历史散装文件夹的兼容包袱，直接重构底层为纯 CBZ 逻辑，消除大量冗余分支判断代码 |
| **CBZ 读取策略** | 内存流式直读 (`archive` 内存解流) | 绝不在磁盘解压任何临时文件，毫秒级流式定位单张图片送交硬件解码，零碎片、最护闪存寿命 |
| **压缩模式** | Store (仅存储，0 压缩等级) | 漫画图片（JPG/WebP）本身已压缩，Store 模式写入速度极快（<0.2秒），极省 CPU、发热与耗电 |
| **下载目录结构** | 根目录纯 CBZ，无子文件夹 | 单话本生成 `[Name].cbz`，多话生成 `[Name]-1.cbz`，封面抽取至应用私有缓存目录，公共目录绝对纯净 |
| **ComicInfo 规范** | 采用 JHenTai 规范标准 | 完整保留 `<Title>`、规范逗号分隔 `<Tags>`，杜绝 EhViewer 将所有微标签塞入 `<Genre>` 导致的媒体库分类污染 |
| **标签汉化翻译** | 复用 PicaComic 内置 EhTagTranslation | 开关控制，直接调用内置词库将微标签及命名空间转换为中文输出到 XML |
| **原始溯源链接** | 官方主站固定链接 / 无网页版则省略 | 采用高稳定性的主站官方路径，便于未来统一维护替换；纯移动端无网页版平台（如哔咔）严格不生成 `<Web>` 节点 |
| **缩略图缓存管理**| 接入系统 `CacheManager` 统一管理 | 缩略图统一存入 `${CacheManager.cachePath}/covers/`，受设置中“缓存限制”严格管控，点击“清除缓存”一并安全清空，并具备 1ms 现场自愈能力 |
| **缩略图生成策略**| 100% 视口按需懒加载 (On-demand) | 下载打包时不生成任何多余文件，仅当滑动列表、漫画进入屏幕视口（`ListView.builder`）时才现场从 CBZ 抽取，未滑到的漫画永远不占缓存 |
| **下载列表手势** | 四象限手势分区（EhViewer 经典逻辑） | 短按封面看详情，短按标题秒进阅读器；长按封面弹离线选话抽屉，长按标题进入多选管理。不修改 UI 界面布局，0 适配破坏风险 |

## 四、 七阶段实施全流程

### 阶段一：基建与设置层打通 (Phase 1)
- 编写 `.github/workflows/build_android.yml`，在云端动态生成合法 keystore，实现无本地环境的全自动化打包。
- 编写 `cbz_config.dart`，使用 SharedPreferences 管理 7 个独立开关。
- 编写 `custom_settings.dart` 独立设置页，并在 `settings_page.dart` 与 `init.dart` 完成挂载。

### 阶段二：自动打包与元数据引擎 (Phase 2)
- 编写 `cbz_builder.dart`，基于 JHenTai 规范构建标准 `ComicInfo.xml`，支持 EhTagTranslation 标签中文化。
- 实现单话平铺（消除 JM 的 `1/` 嵌套）与多话追加序号（`aaa-1.cbz`）打包。
- 在 `download.dart` 的 `_onFinish` 接入自动打包触发器。

### 阶段三：快捷下载规则拦截 (Phase 3)
- 在 `eh_gallery_page.dart` 增加默认普通下载拦截，阻断弹窗。
- 在 `jm_comic_page.dart` 增加自动计算并全选未下载章节逻辑，阻断弹窗。
- 在 `picacg/comic_page.dart` 增加自动全选未下载章节逻辑，阻断弹窗。

### 阶段四：底层管理与阅读器流式直读改造 (Phase 4)
- 适配 `download.dart` 中的 `getCover`、`getEpLength`、`delete`、`deleteEpisode` 到纯 CBZ 模式。
- 编写 `cbz_reader.dart`，使用 `archive` 库从 CBZ 内存直接提取 `Uint8List` 字节流。
- 改造 `file_image_loader.dart` 接入 CBZ 内存流，让全局阅读器无感支持 CBZ 秒读。

### 阶段五：CI 构建优化与架构精简 (Phase 5)
- 解决 Kotlin 2.2.20 基准对齐、AAPT Glance 资源缺失问题。
- 移除 x86 模拟器编译，精简为单一 `arm64-v8a` 架构，将编译时间缩短 50%。

### 阶段六：官方主站溯源链接与缓存自动清理打通 (Phase 6)
- 在 `cbz_builder.dart` 中实现各平台官方固定主站链接的拼接输出，无网页版平台（哔咔）严格省略 `<Web>`。
- 将缩略图落盘目录统一迁至 `${CacheManager.cachePath}/covers/`，复用设置中的缓存上限与一键清理。
- 彻底改为 100% 视口按需懒加载（下载时不生成封面，滑到视口内时现场抽取自愈）。

### 阶段七：下载列表卡片点击/长按手势分区改造 (Phase 7)
- 保持原版 UI 布局不变，在 `DownloadedComicTile` 上实现四象限手势隔离：
  - **短按左侧缩略图** ➜ 方案 A：直接全屏打开原版完整漫画详情页（`toComicInfoPage`）。
  - **短按缩略图以外区域** ➜ 直接秒进阅读器（`comic.read()`），单话直接读，多话自动从历史续读。
  - **长按左侧缩略图** ➜ 呼出本地原版二级抽屉（`showInfo`），供离线选话、单话管理和导出。
  - **长按缩略图以外区域** ➜ 进入多选批量管理模式（原版行为不变）。

### 阶段九：EH 命名空间前缀保留与零侵入元数据增强 (Phase 9)
- 保持官方底层模型 `eh_download_model.dart` 100% 原汁原味不修改，杜绝任何对 App 内搜索、筛选和数据库的潜在影响。
- 在 `cbz_builder.dart` 中以独立函数直接解析 `item.gallery.tags`，仅在生成 `ComicInfo.xml` 时输出标准前缀（英文前缀或规范中文前缀）。
- 自动识别并填充 `<Writer>`、`<Penciller>` 和 `<Characters>` 核心元数据字段。

### 阶段十：用户数据导入导出与 WebDAV 自动同步打通 (Phase 10)
- `CbzConfig` 新增 `toJson()` 与 `fromJson()` 序列化接口。
- 在 `io_tools.dart` 的 `exportDataToFile` 与 `importData` 中挂载 `cbz_config.json` 备份还原。
- 借助 WebDAV 同步底层直接打通，实现全平台多设备（手机/平板/电脑）之间自定义开关的无缝自动漫游。

### 阶段十一：底栏按需保活 (IndexedStack) 极简接入 (Phase 11)
- 在 `navigation_bar.dart` 的 `NaviPaneState` 中引入 `_loadedPages` 懒加载字典与 `IndexedStack`，实现主页、收藏、发现、分类四大主页面的按需初始化与永久保活。
- 恪守最小侵入原则，撤回对 `explore_page.dart`、`comics_list.dart`、`scroll.dart` 滚动体系的侵入式修改，保持 100% 原版纯净度。
- 平时切换 Tab 保持 0 重载、0 延迟与原位像素滚动位置；数据刷新统一交由各页面原生的刷新按钮（FAB / 顶部按钮）处理，兼顾完美的页面保活与极致的代码稳定性。
