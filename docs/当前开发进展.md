# PicaComic 改造开发进展

本项目改造旨在将 PicaComic 打造为以 **同人志 / 短篇单行本** 为核心的高效离线阅读与归档工具。

---

## 阶段一：基建与设置层打通 (Phase 1)
- **状态**：✅ 已完成
- **主要工作小结**：
  1. **GitHub Actions 自动化流水线**：
     - 新建 `.github/workflows/build_android.yml`。
     - 自动解决官方 `key.properties` 签名死锁问题，支持免本地环境的云端全自动发版。
     - 支持 `workflow_dispatch` 手动触发及 tag/push 自动编译，全自动生成按 ABI 分包的 Release APK。
  2. **独立持久化配置层**：
     - 新建 `lib/utils/cbz_config.dart`，基于 `SharedPreferences` 管理 7 个独立开关。
     - 包含自动打包 CBZ、嵌入 ComicInfo、标签汉化、清理原图、EH默认普通下载、JM/Pica默认全选章节。
     - 彻底解耦官方 `appdata.settings` 索引机制，上游更新零冲突。
  3. **设置界面与入口挂载**：
     - 新建 `lib/pages/settings/custom_settings.dart`，提供专属 Material 设置面板。
     - 在 `lib/pages/settings/settings_page.dart` 的“数据与存储”区域添加跳转入口。
     - 在 `lib/init.dart` 启动流中接入 `CbzConfig.init()` 初始化。

## 阶段二：自动打包与元数据引擎 (Phase 2)
- **状态**：✅ 已完成
- **主要工作小结**：
  1. **核心打包与元数据引擎 (`lib/utils/cbz_builder.dart`)**：
     - **ComicInfo.xml 标准化输出**：参考 JHenTai 规范，标准输出 `<Title>`、`<Series>`、`<Number>`、`<Writer>`、`<Penciller>`、`<Tags>`、`<Genre>`、`<Format>`、`<Manga>`（YesAndRightToLeft）及 `<AgeRating>`（Adults Only 18+）。
     - **EhTagTranslation 标签汉化**：智能解析 `namespace:key`，调用内置词库将微标签和命名空间转换为中文输出到 XML。
     - **话数结构规范化打包**：
       - 单话作品（含 JM 的单话嵌套 `1/` 目录）：自动平铺为根目录 `[漫画名称].cbz`。
       - 多话连载：按章节独立压包为 `[漫画名称]-1.cbz`、`[漫画名称]-2.cbz`。
     - **极速 Store 打包**：使用 `archive` 库以 0 压缩等级直存，杜绝二次压缩 JPG/WebP 带来的发热与耗时。
     - **自动清理**：打包成功后自动清理原始碎片目录，释放存储空间。
  2. **下载队列挂钩 (`lib/network/download.dart`)**：
     - 在 `_onFinish()` 尾部仅以 1 行挂钩调用 `CbzBuilder.packageDownloadedComic`，触发自动归档。

## 阶段四：底层管理与阅读器流式直读改造 (Phase 4)
- **状态**：✅ 已完成
- **主要工作小结**：
  1. **流式 CBZ 读取核心 (`lib/utils/cbz_reader.dart`)**：
     - 新建 `CbzReader` 工具类，内置 LRU Central Directory 缓存。
     - 实现 `getImageBytesOrNull()`，直接从 Zip 内存解包单张图片字节流，零磁盘临时文件。
     - 实现 `getCoverFile()`，优先读取缓存封面，丢失时现场从 CBZ 抽取自愈。
     - 实现 `getPageCount()`、`deleteCbz()`、`deleteEpisodeCbz()`，统一接管 CBZ 文件 I/O。
  2. **阅读器图片供给器改造 (`lib/foundation/image_loader/file_image_loader.dart`)**：
     - 在 `_loadAsync()` 中优先请求 `CbzReader.getImageBytesOrNull()`。
     - 命中 CBZ 时直接通过 `ImmutableBuffer.fromUint8List(cbzBytes)` 渲染。
     - 全局阅读器（垂直连续滚动、横向翻页、双页模式、缩略图等）无缝且自动支持 CBZ 直读，完全不需要额外解压。
  3. **下载管理底层适配 (`lib/network/download.dart`)**：
     - `getCover` 转由 `CbzReader.getCoverFile` 供给。
     - `getEpLength` 与 `getComicLength` 支持读取 CBZ 内图片数。
     - `delete` 与 `deleteEpisode` 支持精准删除 `.cbz` 文件和缓存封面。

## 阶段六：官方主站溯源链接与缓存自动清理打通 (Phase 6)
- **状态**：✅ 已完成
- **主要工作小结**：
  1. **官方固定主站溯源链接拼接**：
     - 遵照用户要求，采用稳定性更高的官方固定域名路径，方便未来统一维护与批量全局替换：
       - **E-Hentai**：直接提取真实的画廊绝对链接 `gallery.link`。
       - **Hitomi**：直接提取模型自带的原生画廊链接 `comic.link`。
       - **禁漫 JM**：采用官方主站固定格式 `https://18comic.vip/album/${id}`。
       - **NHentai**：采用官方主站固定格式 `https://nhentai.net/g/${id}/`。
       - **绅士漫画 (HtManga)**：采用官方主站固定格式 `https://www.wnacg.com/photos-index-aid-${id}.html`。
       - **第三方插件源**：若插件自身声明了有效的 `http(s)` 网页地址，拼接为详情页；否则不写入。
       - **哔咔 (Picacg)**：由于官方仅为纯移动端 RPC 接口、无任何官方网页版，**严格不生成 `<Web>` 节点**。
  2. **缩略图完全复用官方 CacheManager 缓存限制管理**：
     - 封面缓存统一存入官方监管目录 `${CacheManager.cachePath}/covers/`。
     - 受用户在设置中自定义的 `limitSize` 上限约束，并在用户点击“清除缓存”时一并清空。
  3. **100% 视口按需懒加载 (On-demand)**：
     - 下载打包时不生成任何封面文件。仅在用户滑动已下载列表、漫画进入屏幕可视区域时现场从 `.cbz` 抽取第 1 张图缓存，没滑到的永远不生成封面。

## 阶段八：内存流式优化与关键漏洞修复专项 (Phase 8)
- **状态**：✅ 已完成（本地已就绪，等待用户指令批量推送）
- **主要工作小结**：
  1. **彻底消除 OOM 与内存暴涨隐患 (`lib/utils/cbz_reader.dart`)**：
     - 弃用全包载入的 `readAsBytesSync()` 与 `decodeBytes()`，全面重构为 `archive.InputFileStream` 文件流解析。
     - 内存中仅缓存排序后的纯文件名列表（`List<String>`），单本漫画索引内存占用降至仅数 KB（降低 99.9% 内存开销）。
     - 实现按需提取单图机制，并加入 5 张图片的微型 LRU 缓存（`_recentImageCache`），兼顾手势翻页极致流畅度与极低内存占用（< 5MB）。
  2. **修复删除漫画抛出异常中断与孤儿文件 Bug (`lib/network/download.dart`)**：
     - 重构 `DownloadManager.delete` 执行时序：在删库前预先锁定提取真实 `dirName`。
     - 改写 `CbzReader.deleteCbz` 直接接收外部 `dirName`，彻底消除由于删库后反查导致的 `Directory not found` 崩溃与物理文件残留。
  3. **修复删除操作遗漏清理页数缓存 Bug (`lib/utils/cbz_reader.dart`)**：
     - 在 `deleteCbz` 与 `deleteEpisodeCbz` 中补全对 `_pageCountCache` 的同步移除逻辑，杜绝内存字典泄漏与重下文件后的页数错乱。
  4. **补全单话删除对 ZIP 扩展名的兼容 (`lib/utils/cbz_reader.dart`)**：
     - 在 `deleteEpisodeCbz` 中同步清理 `.cbz` 与 `.zip` 两种可能存在的文件实体。
  5. **第三方压缩包自然数排序强化 (`lib/utils/cbz_reader.dart`)**：
     - 实现 `_naturalCompare` 正则数字对比算法，确保对第三方异构压缩包中的 `2.jpg` 与 `10.jpg` 100% 正确升序排列，根绝阅读错序隐患。
